Estrutura que dá contexto

0:40 - 1:30 · Mostrar a raiz do repositório e um README de projeto

  • Perfil e apresentação
  • Disciplinas e projetos acadêmicos
  • Projetos pessoais, recursos e documentação
  • READMEs com execução, decisões e limitações
RoteiroO repositório tem quatro áreas principais. A primeira apresenta meu perfil. A segunda separa as disciplinas e suas atividades; no Bootcamp I está a documentação do portfólio web. A terceira reúne projetos pessoais, como o planejador de estudos. A quarta guarda referências utilizadas. Também existem pastas para os documentos editáveis, os PDFs e os testes. A pasta docs contém os arquivos publicados no GitHub Pages. Cada projeto tem um README que explica o objetivo, as tecnologias, como executar e quais são os limites. Essa organização ajuda tanto na revisão das matérias quanto na apresentação do trabalho para outras pessoas.

Um projeto que posso demonstrar

2:20 - 3:25 · Adicionar tarefa, concluir, filtrar e recarregar

  • Planejador de estudos em JavaScript
  • Tarefas com prazo opcional e filtros
  • Persistência local e validação de entradas
  • Regras de dados separadas da interface
RoteiroO projeto pessoal é um planejador de estudos. Vou adicionar uma tarefa, informar um prazo e marcar sua conclusão. O filtro permite mostrar apenas as pendentes ou as concluídas. Quando recarrego a página, a lista permanece porque os dados são salvos no navegador. Não há conta nem sincronização entre dispositivos. Separei as regras das tarefas da parte que manipula a interface; isso permite testar o modelo sem abrir o navegador. A validação rejeita tarefas vazias e datas inexistentes. Se os dados salvos estiverem corrompidos, o sistema tenta preservar os registros válidos. Se o navegador bloquear o armazenamento, o usuário recebe um aviso. Esse projeto me ajudou a praticar eventos, persistência, tratamento de erros e testes.

Mudanças que ficam registradas

3:25 - 4:20 · Mostrar commits, tags, testes e CONTRIBUTING

  • Versão 1.0 e evolução documentada
  • Branch própria para esta entrega
  • Testes do planejador e revisão no navegador
  • Fluxo de colaboração por issues e pull requests
RoteiroO Git registra as mudanças em commits com objetivos específicos. A primeira versão web fica identificada pela tag 1.0.0, e a evolução dos materiais pela versão 1.1.0. O trabalho acontece em uma branch própria, preservando a versão anterior da main até a autorização de integração. Os testes verificam inclusão, conclusão, filtros, exclusão, datas e recuperação de dados. Além deles, é preciso conferir o uso real no navegador. O guia de contribuição explica como abrir uma issue, propor uma alteração e pedir revisão por pull request. O histórico e o changelog permitem acompanhar o que mudou entre as versões.
